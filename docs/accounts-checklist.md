# רשימת חשבונות ושירותים

עקרונות לכל החשבונות:
- נפתחים על מייל העסק `support@orhaalacha.org`, כדי שיהיה קל להעביר ללקוח בסוף.
- אימות דו־שלבי (2FA) מופעל בכל שירות, וקודי הגיבוי נשמרים במקום בטוח.
- סיסמאות במנהל סיסמאות. אף סוד לא נשמר בריפו, בצ'אט או במייל.

## לפתוח עכשיו

### 1. GitHub (החשבון כבר קיים)
- [ ] 2FA מופעל בחשבון.
- [ ] Settings › Code security: להפעיל Secret scanning, ‏Push protection, ‏Dependabot alerts ו־Dependabot security updates.
- [ ] Settings › Branches: חוק הגנה על `main` (ראו למטה).

חוק ההגנה הפעיל (`protect-main`, Settings › Rules › Rulesets): חובה Pull Request (בלי דרישת אישור, כי יש בעלים אחד), חובה שהבדיקות יעברו, בלי force push ובלי מחיקה. רשימת העקיפה כוללת את תפקיד Repository admin ב"תמיד", כדי לאפשר דחיפה ישירה של מסמכי `docs/` בשלב האפיון. קוד עובר תמיד Pull Request.

חוק הגנה מומלץ על `main` (ההגדרה המקורית): חובה Pull Request, חובה שהבדיקות יעברו (`secrets`, `dependency-review`, `workspace (client)`, `workspace (admin)`, `workspace (server)`, `analyze`), בלי force push ובלי מחיקה.

### 2. Cloudflare
- [x] חשבון על `support@orhaalacha.org`.
- [x] הוספת הדומיין `orhaalacha.org` והעברת שרתי ה־DNS אליהם (אצל רשם הדומיין).
  - הדומיין רשום ב־Zoho דרך Tucows. שרתי השמות מוחלפים במסך הניהול של OpenSRS (הקישור ופרטי הכניסה ב־Zoho Mail › דומיינים › פרטי רישום). צריך לפתוח את הנעילה (Domain Locking) לפני השינוי, ולנעול מחדש מיד אחריו.
  - שרתי השמות של Cloudflare: `addilyn.ns.cloudflare.com`, `amit.ns.cloudflare.com`.
  - רשומות המייל (MX ×3, ‏SPF, ‏DKIM) הועתקו ל־Cloudflare ונשארו DNS only. נמחקו דף החניה (A) ו־`www` של Zoho Sites. `mail` הועבר ל־DNS only.
- [x] אישור מ־Cloudflare שהדומיין פעיל (2026-10-27), ובדיקה שהמייל מתקבל ונשלח.
- [x] הוספת רשומת DMARC במצב מעקב: `v=DMARC1; p=none; rua=mailto:support@orhaalacha.org`. להחמיר (`p=quarantine`) אחרי שספק המיילים הטרנזקציוניים יוגדר ב־SPF וב־DKIM.
- [ ] בהמשך: Pages לחנות ולניהול, ו־Access (Zero Trust, מסלול חינמי) לשער של `admin.orhaalacha.org`.

### 3. MongoDB Atlas
- [x] חשבון וארגון (`Or Haalacha`) על `support@orhaalacha.org`, עם אימות דו־שלבי בחשבון ודרישת אימות דו־שלבי לכל חברי הארגון.
- [x] שני פרויקטים נפרדים: `or-haalacha-dev` ו־`or-haalacha-prod`.
- [x] אשכול חינמי (M0) לפיתוח: `or-haalacha-dev`, ב־AWS Frankfurt (eu-central-1), בלי נתוני דוגמה. אשכול הייצור ייווצר כשיוחלט על אחסון השרת, באותו אזור.
- [ ] אשכול לייצור. לייצור יוחלט אחרי שנדע כמה גיבויים ואיזה ביצועים צריך, כי ל־M0 אין גיבויים.
  - פרויקט לא עולה כסף. משלמים לפי אשכול, ומותר אשכול M0 חינמי אחד בכל פרויקט. בינתיים גם בייצור M0, לבדיקות.
  - לפני העלייה לאוויר: לבחור בין מסלול בתשלום עם גיבויים (למשל Flex) לבין M0 עם גיבוי עצמי מתוזמן.
- [ ] משתמש מסד נתונים נפרד לכל סביבה, עם הרשאות מינימליות על מסד אחד בלבד (לא הרשאות ניהול).
  - [x] פיתוח: `or-haalacha-dev-app`, הרשאת `readWrite` על המסד `or-haalacha-dev` בלבד, מוגבל לאשכול הפיתוח. הסיסמה במנהל הסיסמאות.
  - [ ] ייצור: `or-haalacha-prod-app`, באותה תבנית.
- [ ] רשימת כתובות מורשות (Network Access): רק הכתובות הנחוצות. לא `0.0.0.0/0`. לפיתוח אפשר להוסיף את כתובת המחשב שלך.
- [ ] מחרוזות החיבור נשמרות רק במשתני סביבה (ראו `server/.env.example`).
