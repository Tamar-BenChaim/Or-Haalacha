# אפיון מלא – צד לקוח (Angular) – אור ההלכה

מסמך זה מבוסס על:
- ההדמיה האחרונה בקנבס: `Gold3DWhite.dc.html` (רקע לבן, בלי מסגרת) ו־`Gold3DBurgundy.dc.html` (רקע בורדו, עם מסגרת). שתיהן אותו קוד בדיוק ושונות רק בברירות מחדל של שני מתגים (`heroBg`, `frame`). קובץ ההדמיה הוא מקור האמת לעיצוב ולהתנהגות.
- `docs/planning.md` (אפיון), `CLAUDE.md`, `docs/decisions/` (כולל 0009 – Angular), `docs/design-notes.md`, וחוזה ה־API שבענפי השרת `feat/books-api`, ‏`feat/cart-api`, ‏`feat/admin-books` (טרם מוזגו ל־`main`).

סימונים: **[הדמיה]** = קיים בהדמיה. **[אפיון]** = מופיע באפיון ולא בהדמיה. **[הצעה]** = הצעה שלי שדורשת אישור. **[פתוח]** = ממתין להחלטה של הלקוח או של הצוות.

## 0. החלטות והנחות שחובה לאשר לפני שמתחילים

1. **ההחלטה על Angular התקבלה ומוזגה** (PR #8, ‏`docs/decisions/0009-client-angular.md`): `client/` ו־`admin/` ב־Angular, שתי אפליקציות נפרדות. השרת נשאר Node.js. אין צורך ביצירת החלטה חדשה.
2. **משתני סביבה:** אין `.env` בצד לקוח. כתובת ה־API בקבצי `src/environments/environment.ts` (פיתוח) ו־`environment.prod.ts` (ייצור), לפי 0009. הקבצים נשלחים לדפדפן ולכן **בלי סודות**. מפתח Turnstile הציבורי יכול להיות שם.
3. **CORS בשרת:** שרת הפיתוח של Angular רץ על `http://localhost:4200`. צריך להוסיף אותו לרשימת המקורות המותרים בשרת. (שם המשתנה בקובץ `server/.env.example`.)
4. **איזו הדמיה סופית:** הנחתי שהכיוון האחרון הוא הנבחר: בורדו על לבן, כתב סת"ם, כותרת תלת־ממדית. שני המתגים (רקע ומסגרת) ומתג התנועה הם **כלי הדמיה לבחירת הלקוח, לא פיצ'רים של האתר.** באתר האמיתי בוחרים אפשרות אחת. **[פתוח]**
5. **פונט הסת"ם `Stam Ashkenaz CLM` (פרויקט Culmus):** מופץ תחת GNU GPL v2 עם חריג מפורש להטמעה במסמכים. לפני עלייה לאוויר: לצרף את קובץ `LICENSE` של Culmus לצד קובץ הפונט ולוודא מול הנוסח העדכני (לפי `docs/design-notes.md`).
6. **פונטים:** `Noto Serif Hebrew` ו־`IBM Plex Sans Hebrew`. **[הצעה]** לאחסן מקומית (self-host) ולא לטעון מ־Google Fonts, בגלל פרטיות וביצועים.

## 1. מה נכנס לגרסה הראשונה ומה לא

**נכנס (קיים בהדמיה ובאפיון):**
דף בית, דף "הסט המלא", דף ספר, עגלה צדדית, עגלה מלאה, פרטים ותשלום, הצלחה/כישלון, אודות, צור קשר, ארבעה דפים משפטיים, 404, פס הודעה עליון, חיפוש ספרים.

**קיים בהדמיה, לא לממש עד אישור הלקוח** (מסומנים באפיון "לאישור הלקוח"):
- שדה קוד קופון (בעגלה).
- קבלה על שם מוסד/עסק (בטופס).
- תיבת הסכמה לדיוור.
- "עיון בספר" (`preview`) ופרטים טכניים.
- הנחת כמות / הזמנה מוסדית.

מומלץ לבנות אותם מאחורי feature flag בקובץ הסביבה, כדי שהתשובה של הלקוח לא תדרוש שכתוב.

**כלי הדמיה בלבד – לא לממש:** מתג רקע, מתג מסגרת, מתג תנועה, וכפתור "להדמיה: מה רואים כשהתשלום לא הושלם".

## 2. ארכיטקטורה (Angular)

**עקרונות** (מתיישבים עם `CLAUDE.md`: שכבות ברורות, קוד קטן וקריא):
- Angular עדכני יציב, **standalone components** בלבד (בלי NgModules), **signals** למצב, **control flow** חדש (`@if`, `@for`), **Reactive Forms** מוקלדים, **HttpClient** עם interceptors פונקציונליים, ראוטינג עם `loadComponent` (lazy).
- `ChangeDetectionStrategy.OnPush` בכל רכיב.
- TypeScript במצב `strict`.
- אין לוגיקה עסקית ברכיבים: רכיב מציג וקורא ל־service או ל־store.

**מבנה תיקיות** (נבנה כשלד ב־`client/src/app/`; הלוגיקה עדיין לא ממומשת):
```
client/src/app/
├─ core/            # תשתית ונתונים משותפים, בלי UI
│  ├─ models/       # Book, Bundle, CartLine, QuotedLine, ApiErrorBody
│  ├─ http/         # ApiClient, interceptors, מיפוי שגיאות
│  ├─ catalog/      # CatalogStore (GET /books, /bundles, נטען פעם אחת)
│  ├─ cart/         # CartStore (מקור האמת לעגלה, localStorage)
│  ├─ ui/           # UiStore (עגלה צדדית פתוחה, bump)
│  ├─ settings/     # SiteSettingsStore (פס הודעה, משלוחים, טלפון)
│  ├─ storage/      # עטיפה בטוחה ל־localStorage
│  ├─ a11y/         # Announcer (aria-live), ניהול מיקוד
│  ├─ seo/          # Seo (title/meta/og), Share
│  └─ config/       # feature flags
├─ shared/          # רכיבי תצוגה בלבד (input/output, בלי stores):
│                   # book-cover, book-card, qty-stepper, cart-line,
│                   # breadcrumbs, field, skeleton, empty-state
├─ layout/          # shell, announcement-bar, site-header, site-footer, cart-drawer
├─ features/        # כל feature נטען lazy
│  ├─ home/         # home, hero, hero-title, books-section, set-teaser, about-teaser, why-here
│  ├─ set/          # set, shelf
│  ├─ book/         # book, book-gallery, book-nav
│  ├─ cart/         # cart, set-upsell
│  ├─ checkout/     # checkout, order-summary
│  ├─ order/        # order-success, order-failed
│  ├─ content/      # about, legal, not-found
│  └─ contact/      # contact
└─ app.routes.ts    # כל הנתיבים עם loadComponent
```

**כללי תלות** (כיוון אחד בלבד): `app → layout → features → shared → core`.
- feature לא מייבא feature אחר. מה שמשותף עובר ל־`shared/` (תצוגה) או ל־`core/` (נתונים).
- דף (`features/*`) דק: מרכיב רכיבים ומחבר ל־store. רכיבי `shared/` לא מזריקים stores.
- `CartDrawer` ב־`layout/` כי הוא חלק מהמעטפת, ומשתמש רק ב־`CartStore` וב־`shared/cart-line`.
- לא מפרקים רכיב לקטנים מראש; מפרקים כשהוא גדל או נדרש בשני מקומות.
- בלי NgRx, NgModules, Nx או Angular Material (`@angular/cdk` מספיק לנגישות).
- קידומת הרכיבים: `oh-`. שמות הקבצים לפי ברירת המחדל של Angular CLI 21 (בלי סיומת `.component`).

**חיבור לשרת:** שכבת `*.api.ts` לכל תחום (לדוגמה `BooksApi`), שמחזירה Observables מוקלדים. ה־DTO מהשרת ממופה למודל הלקוח במקום אחד.

**מצב:**
- `CartStore` (signals) – מקור האמת היחיד לעגלה.
- `UiStore` – מצב עגלה צדדית פתוחה/סגורה ואנימציית `bump` של כפתור העגלה.
- מצב דף (חיפוש, כמות) נשאר מקומי ברכיב.

**מיפוי מההדמיה ל־Angular:**
| בהדמיה | ב־Angular |
|---|---|
| `this.state.page` + `go(page)` | Router; ניווט מאפס גלילה לראש |
| `scrollTo('books')` | ניווט ל־`/#books` עם `anchorScrolling` |
| `setState`, `renderVals` | signals ו־`computed()` |
| `state.cart` (מילון) | `CartStore` |
| `state.from` (לפירורי לחם) | `state` של הניווט, עם ברירת מחדל "דף הבית" |

## 3. מערכת עיצוב (מתוך ה־CSS של ההדמיה)

להגדיר כ־CSS custom properties על `:root` (או על שורש האפליקציה):

| משתנה | ערך | שימוש |
|---|---|---|
| `--bur` | `#6B1F2A` | צבע ראשי, כפתורים, מחירים, לוגו |
| `--bur-d` | `#521620` | hover של כפתור ראשי |
| `--tint` | `#F8F3F3` | רקע עדין, hover של תפריט, פאנלים |
| `--gold` | `#B8924A` | קו זהב (gold-rule), קישוטים |
| `--gold-l` | `#E6CD8E` | זהב בהיר: טקסט על בורדו |
| `--ink` | `#231C1D` | טקסט ראשי |
| `--muted` | `#5F5658` | טקסט משני |
| `--line` | `#E9E3E1` | קווי הפרדה |
| `--card` / `--card-b` | `#FBF9F9` / `#EFE9E8` | כרטיס ספר ומסגרתו |

צבעי מצב: הצלחה `#2F6B3A`, שגיאה `#A12B2B`.

**טיפוגרפיה:**
- גוף: `IBM Plex Sans Hebrew`, ‏17px.
- כותרות (`h1`, `h2`) וכותרות פאנלים: `Noto Serif Hebrew` משקל 500. `h1` ‏46px, `h2` ‏38px (30px בתתי־מקטעים).
- כתב סת"ם (`StamAshkenaz`) רק ב: לוגו הכותרת העליונה (48px), לוגו התחתית (24px), הכותרת התלת־ממדית בדף הבית, ולוגו על כריכות הספרים. לוגו וכריכות עם `-webkit-text-stroke: .024em` ו־`paint-order: stroke fill`.

**רכיבי UI בסיסיים (כמחלקות או רכיבי `shared/ui`):**
- `btn` (ראשי, גובה 48px), `btn-o` (קווי), `btn-sm` (40px), מצב `disabled` אפור.
- `tl` ו־`lnk`: קישורים בלי קו תחתון; קו רק ב־hover/focus בקישורים בתוך משפט.
- `tile` (כרטיס ספר), `panel`, `tinted`, `field` (תווית + שדה + שגיאה), `qty` (+/−), `crumbs` (פירורי לחם), `gold-rule`, `eyebrow`.
- כריכת ספר: יחס 3:4, גרדיאנט בורדו, צל וגב ספר, בנויה מ־`container-type: inline-size` עם יחידות `cqw`. הכריכה היא CSS (לוגו, קו, נושא, מספר כרך) עד שיגיעו תמונות אמיתיות. **[הצעה]** רכיב `BookCover` שמציג תמונה אמיתית כשיש, ואחרת את כריכת ה־CSS.

**תנועה:** אנימציות `page` (כניסת דף), `drawer`, `bump` (קפיצת כפתור עגלה, 500ms), הנצנצים (`tw`) בכותרת, ו־hover על כריכות. בהדמיה יש 4 סגנונות תנועה (ללא / עדין / ספר נפתח / קפיצה), ובאתר צריך לבחור אחד. `@media (prefers-reduced-motion: reduce)` מבטל **את כל** האנימציות והמעברים (קיים בהדמיה, חובה).

**רספונסיביות:** האתר צריך לעבוד בטלפון. ב־CSS של ההדמיה יש שלושה breakpoints (`max-width`) שמקפלים את הכותרת, האזורים הדו־טוריים והפוטר. רשת הספרים: `repeat(auto-fill, minmax(230px, 1fr))`. המדף בדף הסט נגלל אופקית (`shelf-scroll`).

**כללי עיצוב נוספים מ־`docs/design-notes.md` (חובה):**
- **פינות חדות (ריבועיות)** בכפתורים, כרטיסים, שדות ותגיות. תיבות סימון וכפתורי רדיו נשארים כמו שהדפדפן מציג.
- **זהב רק כקישוט** (קווים דקים, פס הודעה, כריכות). לא לטקסט על רקע לבן (ניגודיות נמוכה).
- **קישורים:** בניווט – בלי קו בכלל. בתוך משפט (תקנון, "בסט המלא") – בורדו מודגש, והקו רק ב־hover ו־focus מקלדת.
- **כפתור העגלה בכותרת:** מלא בבורדו, פינות ריבועיות.
- **דף ספר בטלפון:** כפתור "הוספה לעגלה" קבוע בתחתית המסך.
- **תנועה:** בוחרים סגנון אחד לפני עלייה לאוויר; מכבדים `prefers-reduced-motion`; **לא** מסתירים רכיבים עד גלילה (כדי שלא יישארו אלמנטים נסתרים).
- **כותרת תלת־ממדית:** לפי ההערות, בשימוש אמיתי עדיף לייצא אותה כתמונה קבועה (SVG/PNG), עם `aria-hidden` ו־`h1` אמיתי מוסתר ויזואלית. בכותרות רגילות נשארים בכתב השטוח. **[פתוח]** רקע ומסגרת.
- **פונטים:** הסת"ם לכותרות בלבד, לא לגוף טקסט. לפי ההערות שמות הכריכות ב־Noto Serif Hebrew, ואילו ההדמיה משתמשת בסת"ם ללוגו על הכריכה. **[פתוח]** להכריע.

## 4. ראוטינג

| נתיב | דף | הערות |
|---|---|---|
| `/` | **עמוד ראשי אחד** עם קטעים: פתיחה, `#books`, `#set`, `#about`, `#contact` | הקישורים בתפריט קופצים לקטע, והקישור של הקטע שבמסך מודגש תוך כדי גלילה |
| `/set`, `/about`, `/contact` | הפניה ל־`/#set`, ‏`/#about`, ‏`/#contact` | כתובות ישנות ממשיכות לעבוד |
| `/book/:slug` | דף ספר | כתובת קבועה לשיתוף; slug יציב |
| `/cart` | עגלה מלאה | |
| `/checkout` | פרטים ותשלום | |
| `/order/success` | הזמנה התקבלה | מספר הזמנה ב־query או token |
| `/order/failed` | תשלום לא הושלם | |
| `/legal/:doc` | `terms` · `privacy` · `returns` · `a11y` | |
| `**` | 404 | בעיצוב האתר |

**החלטה (2026-11-07, בעלת הפרויקט, הלקוח נתן יד חופשית): האתר הקטן הוא עמוד ראשי אחד.** הסט המלא, אודות וצור קשר הם קטעים בדף הבית ולא דפים נפרדים (בהדמיה הם היו דפים). דף ספר, עגלה, תשלום והדפים המשפטיים נשארים דפים נפרדים: דף ספר כי משתפים אותו, עגלה ותשלום בגלל החזרה מחברת הסליקה, והמשפטיים כי הם טקסטים ארוכים וחובה לקשר אליהם.

- **קפיצה מיידית** לקטע, בלי אנימציית גלילה (`scroll-behavior: auto`), והקטע נעצר ממש מתחת לסרגל (`core/ui/anchor-offset.ts`: Angular מבצע את הקפיצה בעצמו ומתעלם מ־`scroll-margin`, ולכן מוגדר לו offset בגובה הסרגל, שנקרא בכל קפיצה). הרווח בין הסרגל לכותרת הקטע הוא ה־padding העליון של הקטע (`--section-top`, 40px).
- **הדגשת הקישור הפעיל** (`ScrollSpy`): הקטע האחרון שראשו עבר את הסרגל (בתוספת 48px). בתחתית העמוד מודגש האחרון. באזור הפתיחה אין הדגשה. `aria-current="location"`.
- **אחרי קפיצה** המיקוד עובר לכותרת הקטע, ובמעבר בין דפים ל־`<main>`.
- **טעינה אסינכרונית:** הספרים והסט נטענים אחרי שהדף מוצג ומשנים את גובהו. אם הגעת לקטע נמוך (למשל `/#contact` מדף אחר), הדף קופץ אליו שוב כשהתוכן שמעליו סיים להיטען.
- גלילה לראש בכל ניווט לדף אחר (`scrollPositionRestoration`).
- בכל ניווט: עדכון `<title>`.
- `/checkout` עם עגלה ריקה מפנה ל־`/cart`.

## 5. מעטפת האתר (Layout)

**סדר מלמעלה למטה, בכל דף:**
1. **קישור "דילוג לתוכן הראשי"** (`a.skip`, מופיע ב־focus) לכיוון `#main`.
2. **פס הודעה עליון** [הדמיה]: רקע בורדו, טקסט זהב בהיר, ממורכז: "משלוח חינם בהזמנה מעל [סכום] ₪". אופציונלי; התוכן מגיע מהגדרות השרת (נערך מהניהול). אם אין הודעה – לא מוצג.
3. **כותרת עליונה** (sticky, רקע לבן, קו תחתון): 
   - לוגו בכתב סת"ם, כפתור שמוביל לדף הבית, `aria-label="אור ההלכה – לדף הבית"`.
   - תפריט `nav[aria-label="ניווט ראשי"]`: **הספרים** (גולל ל־`#books` בדף הבית) · **הסט המלא** · **אודות** · **צור קשר**. הפריט הנוכחי מסומן `aria-current="page"` ומודגש. (בהדמיה הסרגל גדול יותר מבגרסאות קודמות: 48px לוגו, 20px תפריט.)
   - כפתור עגלה: אייקון + "עגלה (n)", `aria-label="עגלת קניות, n פריטים"`. מפעיל אנימציית `bump` בהוספה.
4. `<main id="main">`.
5. **כותרת תחתונה** (דקה): לוגו סת"ם קטן + "© כל הזכויות שמורות"; ארבעה קישורים משפטיים; `support@orhaalacha.org · [טלפון]` (כיוון LTR).
6. **עגלה צדדית** (ראו סעיף 8) ו־backdrop.

## 6. דפים

### 6.1 דף בית `/`
1. **Hero** (`section.h3`, `aria-labelledby="hero-title"`):
   - `h1` מוסתר ויזואלית (`.vh`) עם הטקסט "אור ההלכה", כדי שהכותרת התלת־ממדית (שהיא `aria-hidden`) לא תכפיל את הקריאה.
   - הכותרת התלת־ממדית: שני שכבות טקסט זהות (`.ext` להעמקה/אקסטרוזיה ו־`.face` לפנים) בכתב סת"ם, צבע זהב.
   - Eyebrow "סדרת ספרי הלכה", משפט משנה [placeholder], שורת "כ׳ כרכים · מאת הרב [שם המחבר]".
   - שני כפתורים: **"לכל הספרים"** (גולל ל־`#books`) ו־**"הסט המלא"** (`/set`).
   - נצנצים (5 אלמנטים דקורטיביים, `aria-hidden`) ומסגרת זהב עם 4 קישוטי פינה (`.cn1`–`.cn4`) כשהמסגרת פעילה.
2. **"ספרי הסדרה"** (`#books`): כותרת `h2` + קו זהב; **שדה חיפוש** (`input type="search"`, תווית מוסתרת "חיפוש ספר"); טקסט כמות: "20 כרכים", או "מוצגים X מתוך 20" כשיש סינון; רשת כרטיסים; מצב "לא נמצאו ספרים".
   - **כרטיס ספר:** כריכה (לחיצה פותחת את דף הספר), שם (קישור), מחיר, כפתור "הוספה לעגלה". **ספר שאזל** (לפי `design-notes.md`): הכריכה מטושטשת מעט ודהויה, עם תווית "אזל במלאי" ממורכזת עליה (לבן חצי־שקוף, מסגרת וטקסט בבורדו); הכרטיס לא מגיב למעבר עכבר; כפתור ההוספה מושבת. **במסכי מגע** כפתור ההוספה לעגלה מוצג תמיד, עם תווית.
   - החיפוש בהדמיה: `title.indexOf(q)` על שם הספר. **[הצעה]** לנרמל (הסרת ניקוד וגרשיים, רווחים) ולחפש גם בנושא; עם debounce קצר.
3. **הסט המלא** (קטע בבית): כותרת "הסט המלא – 20 כרכים", מדף קטן (`s-sm`) עם 20 גבי ספרים, קישור/כפתור לדף `/set`.
4. **על הסדרה:** כותרת + קו זהב, פסקה קצרה, קישור לאודות.
5. **למה כאן** (קטע תחתון עם קו עליון): שלוש נקודות – "תשלום מאובטח דרך חברת סליקה", "קבלה אוטומטית למייל", "משלוח עד הבית – [זמני משלוח]".

### 6.2 דף הסט המלא `/set` [הדמיה, חדש]
- פירורי לחם: דף הבית › הסט המלא.
- אזור עליון: eyebrow "הצעה מיוחדת", `h1` "הסט המלא – 20 כרכים", תיאור, וכרטיס מחיר: מחיר הסט (בהדמיה 890 ₪), מחיר מחוק (סכום 20 הספרים, 1,180 ₪), "חיסכון של X ₪ לעומת קנייה בנפרד", כפתור **"הוספת הסט לעגלה"**.
  - הנתונים מ־`GET /bundles`: ‏`priceAgorot` (מחיר הסט) ו־`separatePriceAgorot` (סכום הספרים בנפרד). החיסכון הוא ההפרש. אם `separatePriceAgorot` הוא `null` (ספר מוסתר) – לא מציגים שורת חיסכון ומחיר מחוק. **ערכי המחיר מהשרת בלבד.**
- **מדף:** 20 גבי ספרים בגבהים שונים (86%–100%) על קרש. כל גב הוא כפתור עם `aria-label` = שם הספר ועם נושא הספר כתווית אנכית. מעבר עכבר/מיקוד מדגיש את הגב ומציג מתחת (אזור `aria-live="polite"`) "שם הספר · מחיר"; ברירת מחדל: "מעבר על ספר במדף מציג את שמו; לחיצה פותחת את דף הספר". לחיצה פותחת `/book/:slug` עם מקור `set`. במסך צר המדף נגלל אופקית.
- **"הספרים בסט":** רשת של כל הספרים, כמו בבית.

### 6.3 דף ספר `/book/:slug`
- **פירורי לחם** דינמיים לפי מקור הכניסה: דף הבית / עגלת הקניות / הסט המלא (ואז שם הספר כנוכחי). כניסה ישירה או מניווט קודם/הבא → "דף הבית".
- `h1` שם הספר.
- **תמונות:** תמונה ראשית + 4 תמונות ממוזערות (`aria-pressed`): כריכה קדמית, כריכה אחורית, תוכן עניינים, עמוד לדוגמה. **מומש** (`BookGallery`): הכריכה הקדמית תמיד קיימת (תמונה אמיתית או הכריכה המצוירת); שאר התצוגות מופיעות רק אם לספר יש להן תמונה (`images`), ובפיתוח (`showContentPlaceholders`) גם כתיבת דוגמה כמו בהדמיה. כשאין מה לבחור אין ממוזערות. מעבר לספר אחר חוזר לכריכה הקדמית. הגדלה – עוד לא.
- **פרטים:** שם ומספר כרך, מחיר, זמינות, **בחירת כמות** (+ / −, מינימום 1, `aria-live` על המספר), **"הוספה לעגלה"** (מוסיף את הכמות שנבחרה ופותח עגלה צדדית), קישור לסט המלא. ספר שאזל: הודעה "הספר אזל במלאי כרגע", בלי בורר כמות ובלי כפתור.
- **על הספר:** תיאור מלא. **פרטי הספר:** טבלה של מספר עמודים, גודל, כריכה ושנת הוצאה (`details`). **מומש:** בייצור רק שורות שיש להן ערך (ובלי ערכים אין טבלה); בפיתוח שורה ריקה מציגה "[—]". עדיין [פתוח – אילו פרטים הלקוח רוצה].
- **הזמנה לבית כנסת או ישיבה:** תיבה עם קישור "צרו קשר להזמנה מוסדית" אל `/#contact`. **מומש.** שורת "[הנחת כמות / טופס הזמנה מוסדית]" מוצגת רק בפיתוח, עד שהלקוח יחליט.
- **שיתוף:** כפתור שמעתיק את הכתובת ומציג "הקישור הועתק" (`role="status"`). **[הצעה]** `navigator.share` בנייד, עם נפילה להעתקה.
- **עיון בספר – עמודים לדוגמה:** כפתור מתקפל (`aria-expanded`, `aria-controls`) שפותח שלושה עמודים (תוכן עניינים ושני עמודים). **מומש.** העמודים הם תמונות מסוג `contents` ו־`sample`; בייצור הכפתור מופיע רק אם יש כאלה, ובפיתוח מוצגות תיבות דוגמה. נסגר במעבר לספר אחר. [עדיין לאישור הלקוח אם להציג בכלל.]
- **כרך קודם / הבא** (מעגלי: אחרי הכרך האחרון בא הראשון) ו־**"עוד מהסדרה"** (4 ספרים).
- **SEO ושיתוף:** כותרת ותיאור ייחודיים, ו־Open Graph (תמונה, שם, מחיר) – ראו סעיף 13.

### 6.4 עגלה מלאה `/cart`
- `h1` "עגלת הקניות".
- שורה לכל פריט: כריכה/תמונה, שם (**לחיצה על השורה פותחת את דף הספר, או את דף הסט** [הדמיה, חדש]), מחיר ליחידה, כמות (+ / −; ירידה ל־0 מסירה), כפתור הסרה (`aria-label="הסרה מהעגלה"`, שטח לחיצה 44px), סכום שורה.
- **הצעת הסט:** מוצגת כשיש בעגלה 5 שורות ספרים בודדים או יותר ואין סט. הלחיצה בהדמיה **מחליפה את כל תוכן העגלה בסט אחד**. **[פתוח]** לאשר את ההתנהגות; **[הצעה]** להציג את הסכום לחיסכון ולבקש אישור לפני החלפה.
- **סיכום:** סכום ביניים; דמי משלוח – "יחושבו בשלב הבא"; כפתור "לתשלום" ו"להמשך קנייה".
- שדה קוד קופון + "החלה" [הדמיה, לאישור].
- **עגלה ריקה:** הודעה וכפתור "לכל הספרים".

### 6.5 פרטים ותשלום `/checkout`
טופס בפאנלים; שדות עם `*` הם חובה. **הדמיה:** סדר השדות והתוויות. **[הצעה]:** כללי האימות (הלקוח לנוחות בלבד; האימות האמיתי בשרת).

**פרטי המזמין:**
| שדה | חובה | הערות |
|---|---|---|
| שם מלא (`name`) | כן | `autocomplete="name"`; 2–80 תווים |
| טלפון (`phone`) | כן | `type="tel"`, `autocomplete="tel"`; מספר ישראלי (נייד/קווי), מקבל מקפים/רווחים וכל הנורמליזציה בשרת |
| מייל (`mail`) | כן | `type="email"`, `autocomplete="email"` |

**משלוח** (`radiogroup`, `aria-label="אופן משלוח"`): משלוח עד הבית · נקודת איסוף · איסוף עצמי [כתובת]. אפשרויות ומחירים מגיעים מהשרת (בהדמיה: 30 ₪ / 20 ₪ / חינם). **עיר, רחוב, מספר** חובה; **דירה, מיקוד** אופציונליים; **הערות להזמנה** אופציונלי (עד אורך מוגבל). כל שדות הכתובת מוסתרים באיסוף עצמי. 

**קבלה על שם מוסד** [לאישור]: תיבת סימון שחושפת "שם המוסד/העסק" ו"ח"פ / ע"מ" (ספרות; **[הצעה]** בדיקת ספרת ביקורת של מספר עוסק בשרת).

**הסכמות:**
- **תקנון ומדיניות פרטיות – חובה**, לא מסומנת מראש. הטקסט כולל קישורים לשני המסמכים (נפתחים בלשונית חדשה כדי לא לאבד את הטופס; בהדמיה הם מנווטים באותו חלון ומאבדים מצב, ולכן **[הצעה]** לשינוי).
- דיוור – לא מסומנת מראש [לאישור הלקוח].
- ללא אישור: שגיאה `role="alert"` "כדי להמשיך יש לאשר את התקנון ואת מדיניות הפרטיות", מקושרת ב־`aria-describedby`.

**סיכום הזמנה (צד):** שורות "שם × כמות — סכום", סכום ביניים, משלוח, **סה"כ לתשלום**, כפתור **"לתשלום מאובטח"** (עם אייקון מנעול) והערה "התשלום מתבצע בדף המאובטח של חברת הסליקה. פרטי האשראי לא נשמרים באתר."

**התנהגות הכפתור (בהדמיה קיים רק בדיקת תקנון; באתר האמיתי):**
1. אימות כל הטופס; אם יש שגיאות – מיקוד לשדה הראשון עם שגיאה וסיכום שגיאות מוקרא.
2. השבתת הכפתור והצגת מצב טעינה (מניעת לחיצה כפולה).
3. `POST /orders`: השרת מחשב מחדש מחירים ומלאי, יוצר הזמנה "ממתינה לתשלום" ומחזיר כתובת של חברת הסליקה.
4. הפניה (`window.location`) לדף התשלום. **העגלה לא מתרוקנת בשלב זה.**
5. שגיאת ולידציה מהשרת (`VALIDATION_ERROR`) ממופה לשדות לפי `details`. שינוי מחיר/מלאי → חזרה לעגלה עם הודעה.

### 6.6 הצלחה וכישלון
- **`/order/success`** – `h1` "תודה, ההזמנה התקבלה": מספר הזמנה, מספר פריטים, סה"כ ששולם, "שלחנו אישור הזמנה וקבלה למייל שלך", כפתור "חזרה לדף הבית".
  - **בהדמיה הנתונים מגיעים ממצב מקומי והעגלה מתרוקנת מיד.** באתר האמיתי **ההצלחה חייבת להיבדק מול השרת** (`GET /orders/:token/status`), והעגלה מתרוקנת רק אחרי שהשרת מאשר תשלום (החלטת מוצר מ־`planning.md`). אסור להסתמך רק על כתובת (query) כדי לנקות עגלה או להציג "שולם".
  - מצב ביניים: אם התשלום עדיין לא אושר (ה־webhook מאחר) – "ממתינים לאישור התשלום", ובדיקה חוזרת מוגבלת.
- **`/order/failed`** – "התשלום לא הושלם. לא חויבת. הספרים עדיין שמורים בעגלה, ואפשר לנסות שוב." כפתורים "לנסות שוב" (חזרה ל־checkout) ו"צריך עזרה?" (צור קשר). העגלה נשמרת.

### 6.7 אודות `/about`
`h1` "על הסדרה", eyebrow, קו זהב, שתי פסקאות [טקסט מהלקוח], כפתור "לכל הספרים", ו־**"מהשיעורים"**: **שלוש תמונות באותו גודל באותה שורה** (יחס 4:3) [שינוי בהדמיה האחרונה; בגרסה הקודמת היו שש]. במסך צר – מתקפלות.

### 6.8 צור קשר `/contact`
- מייל וטלפון לחיצים (`mailto:`, `tel:`).
- טופס (פאנל `tinted`): **שם \***, **מייל או טלפון \***, נושא, **הודעה \***.
- הגנת **Cloudflare Turnstile** והגבלת קצב (מהאפיון; לא נראה בהדמיה).
- שליחה: `POST /contact`. מצב הצלחה: "ההודעה נשלחה. נחזור אליך בהקדם." (`role="status"`). טיפול ב־`RATE_LIMITED` (הודעה ידידותית) ובשגיאת שרת עם אפשרות לנסות שוב. ההודעה נשלחת למייל ולא נשמרת במסד.

### 6.9 דפים משפטיים `/legal/:doc`
ארבעה מסמכים: **תקנון האתר**, **מדיניות פרטיות**, **ביטולים והחזרות**, **הצהרת נגישות**. בהדמיה: תפריט צד עם ארבעת המסמכים + `h1` + מקטעים (כותרת + פסקת placeholder):
- תקנון: פרטי העסק · תהליך ההזמנה · מחירים ותשלום · משלוחים וזמני אספקה · ביטולים והחזרות · אחריות · יצירת קשר.
- פרטיות: איזה מידע אנחנו אוספים · למה משתמשים בו · למי מועבר · היכן נשמר וכמה זמן · הזכויות שלך · אחסון בדפדפן · פניות בנושא פרטיות.
- ביטולים: לפני משלוח · לאחר קבלה · ספר פגום/שגוי · אופן ההחזר.
- נגישות: רמת הנגישות · מה הונגש · מגבלות ידועות · רכז נגישות · תאריך עדכון.

**[הצעה]** התוכן כקבצי Markdown/HTML ב־`assets`, כך שהנוסח הסופי (אחרי עורך דין) מוחלף בלי לגעת בקוד. המסמך "אחסון בדפדפן" חייב לתאר את שמירת העגלה ב־localStorage.

### 6.10 דף 404
בעיצוב האתר: "הדף לא נמצא" וכפתור חזרה לדף הבית.

## 7. מצב העגלה (`CartStore`)

**מודל:**
```ts
type CartItemRef =
  | { type: 'book'; slug: string }
  | { type: 'bundle'; slug: string };   // כרגע רק 'full-set'

interface CartLine { ref: CartItemRef; quantity: number }   // ב־localStorage: רק slug וכמות

// תשובת POST /cart/quote לכל שורה
interface QuotedLine extends CartLine {
  title: string | null; unitPriceAgorot: number | null; lineTotalAgorot: number;
  requestedQuantity: number;
  status: 'ok' | 'limited' | 'out_of_stock' | 'unavailable';
}
```
(בהדמיה המפתח הוא מחרוזת: `b0..b19` או `set`. באתר האמיתי העגלה מזהה מוצר לפי `slug`, כמו ב־API. כל הסכומים באגורות.)

**פעולות (signals):** `lines`, `count` (סכום כמויות; מוצג ב"עגלה (n)"), `isEmpty`, `subtotal`, `bookLineCount`, `showSetUpsell` (`bookLineCount >= 5` ולא קיים סט).
`addItem(ref, qty)`, `setQty(ref, qty)` (qty ≤ 0 מסיר), `remove(ref)`, `replaceWithSet()`, `clear()`, `revalidate()`.

**כללים:**
- **שמירה:** ב־localStorage תחת מפתח עם גרסה (לדוגמה `oh.cart.v1`), בכל שינוי. קריאה בטוחה: `try/catch`, בדיקת סכמה, וניקוי נתונים פגומים. אם localStorage חסום – העגלה חיה בזיכרון בלבד, בלי קריסה. סנכרון בין לשוניות באמצעות אירוע `storage`.
- **אין אמון בדפדפן:** המחירים שמוצגים בעגלה הם מהשרת. `revalidate()` נקראת בכל פתיחת עגלה (צדדית או מלאה) ובכניסה ל־checkout.
- **שינויים:** שינוי מחיר, ספר שאזל או הוסר מהקטלוג – מוצג בהודעה ברורה (`aria-live`), ספר שאזל מסומן ולא ניתן לרכישה. 
- **הוספה:** פותחת עגלה צדדית ומפעילה `bump` (חוץ ממצב בלי תנועה).
- כמות מקסימלית לשורה: **[הצעה]** תקרה (לדוגמה 99), ובהתאם למלאי אם השרת מחזיר.

## 8. עגלה צדדית (Drawer)

## 9. חוזה API

מקור: `docs/api.md` בענפי השרת `feat/books-api`, ‏`feat/cart-api`, ‏`feat/admin-books`. **הענפים טרם מוזגו ל־`main`, והחוזה עשוי להשתנות** – לתאם עם מפתח השרת לפני שנועלים. ב־`main` קיים כרגע רק `GET /health`.

**סכומים:** תמיד מספרים שלמים באגורות, בשדות שמסתיימים ב־`Agorot` (`6500` = 65 ₪). הלקוח מציג דרך pipe אחד (`agorotToShekels`) ולא מחשב בשבר צף. ההדמיה מציגה שקלים שלמים.

### נקודות שקיימות בענפי השרת (הלקוח משתמש בהן)
| שיטה ונתיב | תפקיד | תשובה |
|---|---|---|
| `GET /books` | הספרים המוצגים, לפי סדר ההצגה | `{ books: [{ id, slug, title, volume, shortDescription, priceAgorot, inStock, coverImage }] }` |
| `GET /books/:slug` | ספר בודד | `{ book }` עם `description` נוסף. `404 BOOK_NOT_FOUND` אם לא קיים או מוסתר |
| `GET /bundles` | הסט המלא | `{ bundles: [{ id, slug, title, description, priceAgorot, separatePriceAgorot, inStock, books[] }] }` |
| `POST /cart/quote` | חישוב מחדש של העגלה בשרת | גוף: `{ items: [{ type: 'book'\|'bundle', slug, quantity }] }` → `{ items[], subtotalAgorot, allAvailable }` |

- `volume` יכול להיות `null`. `coverImage` הוא `{ url, alt }` או `null` (אחסון תמונות טרם נבחר). `inStock` הוא בוליאני; כמות המלאי לא נחשפת.
- **`/cart/quote`:** עד 50 שורות, כמות 1 עד 99 (הלקוח מגביל לפי זה). מחירים שנשלחים מהדפדפן מתעלמים. נקראת בכל פתיחת עגלה (צדדית ומלאה) ובכניסה ל־checkout.
- **סטטוס שורה בתשובה:**
  | `status` | התנהגות בלקוח |
  |---|---|
  | `ok` | רגיל |
  | `limited` | מעדכנים לכמות שהחזיר השרת (`quantity`) ומציגים הודעה "במלאי רק X" |
  | `out_of_stock` | השורה מסומנת "אזל", אי אפשר להזמין, אפשר להסיר |
  | `unavailable` | `title` ו־`unitPriceAgorot` הם `null`; מסירים מהעגלה עם הודעה |
- `allAvailable: false` – חוסמים מעבר ל־checkout עד שהקונה מטפל בשורות.
- דמי משלוח **לא** נכללים ב־`subtotalAgorot` ומחושבים בשלב ההזמנה.

### נקודות שעדיין לא קיימות (צריך מהשרת)
- `POST /orders` – יצירת הזמנה "ממתינה לתשלום" והחזרת כתובת חברת הסליקה (בסשן ההזמנות קיימת תוכנית ל־`feat/orders`, אבל לא ראיתי ענף כזה).
- `GET /orders/:token/status` – מצב הזמנה לדף הצלחה.
- `POST /contact` – פנייה (עם Turnstile).
- הגדרות ציבוריות: פס הודעה עליון, אפשרויות ומחירי משלוח, סף משלוח חינם, טלפון ומייל.
- `POST /cart/coupon` – רק אם הלקוח יאשר קופון.

### שדות שההדמיה מציגה ואין ב־API
- **נושא הספר** (`topic`, לדוגמה "הלכות שבת") – ב־API יש רק `title` ו־`volume`. לבקש שדה או להחליט שהנושא חלק מהכותרת.
- **ארבע תמונות** (כריכה קדמית ואחורית, תוכן עניינים, עמוד לדוגמה) – ב־API יש `coverImage` יחיד. **הלקוח כבר מוכן לקבל** `images: [{ kind: 'front' | 'back' | 'contents' | 'sample', url, alt }]` (אפשר כמה מסוג `sample`), ב־`GET /books/:slug`.
- **פרטים טכניים** – אין. **הלקוח כבר מוכן לקבל** `details: { pages, size, binding, year }`, וכל שדה יכול להיות `null`.
- **גובה גב המדף** – אין. הגובה אפשר לחשב בלקוח.
- **מספר הכרך** – משתמשים ב־`volume`.

### שגיאות
מבנה `{ error: { code, message, details }, requestId }`. קודים שהלקוח מטפל בהם: `VALIDATION_ERROR` (שדות, לפי `details`), `INVALID_JSON`, `INVALID_INPUT`, `BOOK_NOT_FOUND`, `NOT_FOUND`, `PAYLOAD_TOO_LARGE`, `UNSUPPORTED_MEDIA_TYPE` (בקשות POST חייבות `Content-Type: application/json`), `RATE_LIMITED`, `INTERNAL_ERROR`. קודי `UNAUTHENTICATED` ו־`FORBIDDEN` שייכים לנתיבי `/admin` בלבד. בהודעת תקלה כללית מציגים את `requestId` (כותרת `X-Request-Id`). נתיבי `/admin` לא בשימוש בחנות.

## 10. טפסים ואימות (Angular)

- Reactive Forms מוקלדים (`FormGroup<...>`), פונקציית אימות לכל כלל, ו־`ErrorMessagePipe` שממפה שגיאה להודעה בעברית.

- שגיאות שרת ממופות לשדות לפי `details` (מיקום, שדה, הודעה).

## 13. SEO ושיתוף (אפשר לדחות)

**מה הבעיה:** כשמשתפים קישור לספר ב־WhatsApp או במייל, האפליקציה שמציגה את התצוגה המקדימה (תמונה, שם, מחיר) מורידה את קוד ה־HTML של הדף **ולא מריצה JavaScript**. אתר Angular רגיל (CSR) מחזיר דף כמעט ריק ושם הספר נבנה רק בדפדפן, ולכן התצוגה המקדימה תהיה כללית או ריקה. גוגל כן מריץ JavaScript, ולכן החיפוש בו פחות מושפע.

**למה זה בכלל באפיון:** `planning.md` דורש "תצוגה מקדימה עשירה ב־WhatsApp ובמייל" ו"כתובת קבועה לכל ספר". אם רוב הקונים מגיעים ישירות מהרשת והשיתוף משני, זו דרישה משנית.

**המלצה:** לא חוסם את תחילת הבנייה.
1. בונים עכשיו כרגיל (CSR), בלי SSR, כמו בפקודת `ng new` שב־`client/README.md`.
2. כבר עכשיו: כתובת יציבה `/book/:slug`, ו־`Title`/`Meta` (כולל תגיות `og:*`) לכל דף. הן יעבדו מיד כשתהיה תצוגה מקדימה.
3. אם אחר כך יתברר שצריך תצוגה מקדימה: או להוסיף `@angular/ssr` לפרויקט קיים, או פונקציית קצה (Cloudflare) שמחזירה HTML עם התגיות רק לבוטים. שתי הדרכים אפשריות גם בדיעבד, אבל ההוספה בהמשך דורשת עבודה ובדיקה מחדש של האחסון.
4. בכל מקרה: `robots.txt`, ‏`sitemap.xml` ונתוני JSON־LD מסוג `Product`.
