# 0010 – אימות פעולות הניהול בשרת

סטטוס: התקבלה

## הקשר
אזור הניהול (`admin.orhaalacha.org`) והשרת (`api.orhaalacha.org`) נמצאים בכתובות שונות. החלטה 0003 קבעה שתי שכבות הגנה: Cloudflare Access, ובנוסף בדיקה בשרת לכל פעולת ניהול.

## החלטה
- **אפליקציית Access אחת** ב־Cloudflare מכסה את אזור הניהול ואת הנתיבים `api.orhaalacha.org/admin/*`. אחרי כניסה עם קוד למייל, הדפדפן שולח את עוגיית Access גם לשרת (‏`credentials: 'include'`), ו־Cloudflare מוסיף לכל בקשה אישור חתום בכותרת `Cf-Access-Jwt-Assertion`.
- **השרת בודק בכל בקשת ניהול** (`requireAdmin`):
  - את חתימת האישור, מול המפתחות הציבוריים של צוות Cloudflare (`/cdn-cgi/access/certs`);
  - את המנפיק (issuer);
  - את הקהל (audience), כלומר שהאישור שייך לאפליקציה שלנו;
  - את התוקף;
  - שהמייל נמצא ב־`ADMIN_EMAILS`.

  הבדיקה נעשית עם הספרייה `jose`. אישור חסר או לא תקין מחזיר 401, ומייל לא מורשה מחזיר 403.
- **CORS:** נתיבי `/admin` פתוחים רק ל־`ADMIN_ORIGIN`, עם credentials. נתיבי החנות פתוחים לכתובות החנות, בלי credentials.
- **הגנה מפני זיוף בקשות (CSRF):** פעולות שמשנות נתונים מקבלות רק `application/json`. כך הדפדפן חייב לשלוח קודם בקשת בדיקה (preflight), שנכשלת מכל אתר אחר.
- **פיתוח מקומי:** ‏`ADMIN_DEV_EMAIL` מדלג על Access ומתייחס לכל בקשת ניהול כאילו הגיעה מהמנהל הזה. השרת מסרב לעלות איתו בייצור, ומזהיר בלוג כשהוא מוגדר.
- **בייצור חובה** להגדיר `CF_ACCESS_TEAM_DOMAIN` ו־`CF_ACCESS_AUD`.

## הגדרות נדרשות ב־Cloudflare (בשלב הפריסה)
- אפליקציית Access מסוג Self-hosted עם שתי כתובות: `admin.orhaalacha.org` ו־`api.orhaalacha.org/admin`.
- מדיניות: Allow, עם הכלל Emails = `support@orhaalacha.org`, ואימות בקוד חד־פעמי למייל.
- הגדרות CORS באפליקציה: לאפשר credentials מ־`https://admin.orhaalacha.org`, ולהעביר בקשות OPTIONS לשרת (Bypass options requests to origin).
- להעתיק את תג ה־AUD של האפליקציה ל־`CF_ACCESS_AUD`.

## נימוקים וחלופות
- הסתמכות על Access בלבד נפסלה: אם מישהו יגיע לשרת שלא דרך Cloudflare, או אם ההגדרה תשתנה בטעות, השרת עדיין מגן.
- מערכת התחברות עצמאית בשרת (סיסמה ועוגיות) נפסלה: זה עוד קוד אבטחה רגיש לתחזק, כש־Access כבר נותן כניסה עם קוד למייל.
- נשקל להעביר את קריאות הניהול דרך כתובת אזור הניהול עצמה (אותו מקור), אבל זה מוסיף שכבת תיווך ב־Cloudflare בלי יתרון אבטחה ממשי.
