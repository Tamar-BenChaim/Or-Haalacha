# 0006 – ספריות ומבנה השרת

סטטוס: התקבלה

## הקשר
צריך שרת API קטן, מאובטח וקל לבדיקה, שיתאים לכל אחת מאפשרויות האחסון שבהחלטה 0004.

## החלטה
- **Node.js 22 עם ES Modules** ו־**Express 5**, שמעביר שגיאות מפונקציות async למטפל השגיאות בלי קוד נוסף.
- **zod**: אימות משתני הסביבה בעלייה (השרת לא עולה אם חסר משתנה), ואימות קלט בכל נקודת API.
- **helmet**, ‏**cors** עם רשימת כתובות מורשות, ‏**express-rate-limit**.
- **pino** ללוגים בפורמט JSON.
- **Vitest + Supertest** לבדיקות יחידה ואינטגרציה. **ESLint + Prettier** לסגנון.
- שכבות: routes → controllers → services → data access. כל שכבה נוצרת בפונקציה שמקבלת את התלויות שלה, בלי מחלקות ובלי ספריית הזרקת תלויות.
- `app.js` בונה את האפליקציה בלי להאזין, ו־`server.js` מפעיל אותה. כך הבדיקות מריצות את האפליקציה המלאה בלי פורט.
- הספרייה לגישה למסד (הדרייבר הרשמי `mongodb` מול Mongoose) תיבחר בשלב חיבור המסד, ותתועד בהחלטה נפרדת.

## נימוקים וחלופות
- Express הוא הבחירה הנפוצה והמתועדת ביותר, ומספיק לשרת בגודל הזה. Fastify ו־NestJS נשקלו: NestJS כבד מדי לפרויקט, ו־Fastify לא מביא יתרון משמעותי כאן.
- zod משמש גם לקלט וגם להגדרות, כך שיש כלי אחד לאימות.
- Jest נשקל, ו־Vitest נבחר כי הוא תומך ב־ES Modules בלי הגדרות, ומשותף גם לצד הלקוח (Vite).
