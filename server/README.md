# server – שרת ה־API

שרת Node.js (Express 5) שמשרת את החנות ואת אזור הניהול. תיעוד הנקודות: [docs/api.md](../docs/api.md).

## הרצה מקומית

דרישות: Node.js 22.9 ומעלה.

```bash
cd server
npm install
cp .env.example .env     # למלא ערכים מקומיים; הקובץ לא נכנס ל־git
npm run dev              # מריץ עם טעינה מחדש בכל שינוי
```

השרת לא עולה אם משתנה סביבה חסר או לא תקין, ומדפיס את שם המשתנה (בלי הערך). הוא גם לא עולה אם אין חיבור למסד הנתונים.

לפיתוח מקומי צריך MongoDB: מסד הפיתוח ב־Atlas, או מסד מקומי, למשל:

```bash
docker run -d --name mongo -p 27017:27017 mongo:8.0
```

## בדיקה ב־Postman

1. מפעילים את השרת (`npm run dev`) וממלאים נתוני דוגמה (`npm run seed`).
2. ב־Postman: ‏**Import** ובוחרים את הקובץ `postman/or-haalacha.postman_collection.json`.
3. שולחים כל בקשה בנפרד, או מריצים את כל האוסף: לחיצה ימנית על האוסף › **Run collection**.
4. בלשונית **Test Results** של כל בקשה רואים אילו בדיקות עברו.

כתובת השרת מוגדרת במשתנה `baseUrl` של האוסף (ברירת המחדל: `http://localhost:3000`).

## בדיקות ומסד הנתונים

בדיקות האינטגרציה רצות מול MongoDB אמיתי, ולא מול Atlas:

- אם מוגדר `MONGODB_TEST_URI`, הבדיקות משתמשות בו (למשל בקונטיינר המקומי שלמעלה).
- אחרת הן מפעילות אוטומטית MongoDB בזיכרון (`mongodb-memory-server`). בהרצה הראשונה הוא מוריד את MongoDB, וזה לוקח כמה דקות.

כל קובץ בדיקות עובד על מסד נפרד עם שם אקראי, ומוחק אותו בסיום.

## מבנה

```
src/
  server.js        הפעלה: טעינת הגדרות, האזנה וכיבוי מסודר
  app.js           בניית אפליקציית Express (בלי האזנה, בשביל הבדיקות)
  config/          אימות משתני הסביבה עם zod
  middleware/      אבטחה, מזהה בקשה, לוג בקשות, אימות קלט, שגיאות
  routes/          הגדרת הנתיבים וחיבור השכבות
  controllers/     קריאת הבקשה והחזרת תשובה
  services/        הלוגיקה העסקית
  data/            גישה למסד: חיבור, אינדקסים וקובץ לכל אוסף (repository)
  logging/         מאגר הלוגים של הבקשות
  lib/             כלים משותפים
test/
  unit/            בדיקות יחידה
  integration/     בדיקות של האפליקציה כולה ושל שכבת הנתונים מול MongoDB
  setup/           הפעלת MongoDB לבדיקות
scripts/
  seed.js          מילוי מסד הפיתוח בנתוני דוגמה
postman/           אוסף בקשות מוכן לבדיקה ב־Postman
```

סדר השכבות: routes → controllers → services → data access. כל שכבה מקבלת את התלויות שלה כפרמטר, וכך קל לבדוק אותה בנפרד.

## אבטחה

- כותרות אבטחה (helmet), ‏CORS רק לכתובות שב־`CORS_ORIGINS`, הגבלת קצב לכל כתובת IP.
- גוף בקשה עד 100KB, ו־JSON בלבד.
- דחיית שמות שדות שמתחילים ב־`$` או מכילים `.`, וגם `__proto__` ודומיו (NoSQL injection ו־prototype pollution).
- אימות קלט לכל נקודה עם `validate({ params, query, body })` וסכמות zod. הערכים המאומתים נמצאים ב־`req.validated`.
- שגיאה לא צפויה מחזירה ללקוח הודעה כללית עם מזהה בקשה. הפרטים נשמרים רק בלוג.

## מסד הנתונים

גישה עם הדרייבר הרשמי `mongodb` (החלטה [0008](../docs/decisions/0008-mongodb-driver.md)). רק התיקייה `data/` מכירה את הדרייבר. האינדקסים נוצרים בכל עלייה של השרת, והפעולה בטוחה גם כשהם כבר קיימים.

| אוסף           | תוכן               | שמירה  |
| -------------- | ------------------ | ------ |
| `request_logs` | לוג לכל בקשה       | 90 יום |
| `audit_logs`   | יומן פעולות עסקיות | שנתיים |

## לוגים

ראו החלטה [0007](../docs/decisions/0007-server-logging.md).

- **לוג בקשות:** כל בקשה נשמרת בסיומה ב־`request_logs`: זמן, מזהה בקשה, שיטה, נתיב (בלי פרמטרים), סטטוס, משך וכתובת IP מקוצרת. לא נרשמים גוף הבקשה, כותרות או פרטים אישיים.
- **יומן פעולות:** `auditService.record({ actor, action, entityType, entityId, changes })` שומר פעולה עסקית ב־`audit_logs`. למשל `action: 'book.update'`, ‏`changes: { price: { from: 60, to: 65 } }`. מעבירים רק שדות עסקיים, ולעולם לא פרטי קונים. רשומה לא תקינה זורקת שגיאה, כי זו טעות בקוד.
- **כשל ברישום** (למשל כשהמסד לא זמין) נרשם בפלט השרת, ולא פוגע בבקשה או בפעולה.
- **שגיאות פנימיות מלאות** נרשמות רק בפלט השרת (pino).
